### Assets

| File | What it is |
|---|---|
| `LocalDocks_0.9.0_x64-setup.exe` | The NSIS installer, per-user, x64. Built by `npx tauri build` |
| `SHA256SUMS.txt` | One line, `<hash>  <filename>`, so the download can be verified |

Source archives are attached by GitHub automatically.

**Why no MSIX and no `.msi`:** the Store package does not exist yet
([STORE-LISTING.md](../STORE-LISTING.md)), and an MSI would be a second,
untested installer for a product that ships one.

### The checksum is filled in at publish time, on purpose

The installer's hash cannot live in the commit the installer is built from — the
hash would change the commit, which would change the hash. So it is generated
after the build and pasted into the release body and `SHA256SUMS.txt`:

```powershell
$pkg = "src-tauri/target/release/bundle/nsis/LocalDocks_0.9.0_x64-setup.exe"
$h = (Get-FileHash $pkg -Algorithm SHA256).Hash.ToLower()
"$h  $(Split-Path $pkg -Leaf)" | Set-Content SHA256SUMS.txt -Encoding ascii
```

**If the installer is ever code signed, this hash changes.** Signing means
rebuild, re-hash, re-publish — never re-signing a file that has already been
released.

## 2 · Release body — paste as-is, then fill the two marked fields

> ## LocalDocks v0.9.0 — release candidate
>
> A local development dashboard for Windows. It shows the services, processes
> and listening ports you own, alongside machine CPU, memory, network, storage,
> GPU and thermal telemetry.
>
> It runs without administrator rights and never asks for them. It has no
> network client, no analytics and no account — every measurement stays on your
> machine. When something cannot be measured, it says so rather than showing a
> zero.
>
> This is a **release candidate**. It is complete and verified, but it has not
> been in anyone else's hands yet. Please report what breaks.
>
> ### Install
>
> Download `LocalDocks_0.9.0_x64-setup.exe` and run it. It installs per-user to
> `%LOCALAPPDATA%\LocalDocks` and needs no administrator rights.
>
> **Windows will warn you.** This build is not code signed, so SmartScreen shows
> *"Windows protected your PC"* — choose **More info → Run anyway**. That is
> expected, and the reasoning is written up in
> [docs/CODE-SIGNING.md](https://github.com/jayranedev/LocalDocks/blob/main/docs/CODE-SIGNING.md).
> Verify the download first if you would rather not take that on trust:
>
> ```powershell
> Get-FileHash .\LocalDocks_0.9.0_x64-setup.exe -Algorithm SHA256
> ```
>
> ```
> SHA-256: <FILL IN FROM SHA256SUMS.txt>
> ```
>
> ### Requirements
>
> Windows 10 1809 (build 17763) or later, x64. The Microsoft Edge WebView2
> Runtime is required; it ships with Windows 11 and current Windows 10, and the
> installer fetches it if it is missing.
>
> ### What is in it
>
> <FILL IN: the "Added" section of CHANGELOG.md for 0.9.0>

## 3 · Order of operations

Each step is gated on the one before it. **None of them has been performed.**

1. Merge `feature/release-hardening` into `main`. *(Not done — merging was
   explicitly out of scope for release preparation.)*
2. Re-run the full verification on the merged `main`
   ([RELEASE.md § Cutting a release](../RELEASE.md#cutting-a-release)).
3. `npx tauri build` from that exact commit.
4. Reinstall from the produced installer and smoke-test: launch, all screens,
   close, relaunch, uninstall.
5. Generate `SHA256SUMS.txt` with the command in section 1.
6. `git tag -a v0.9.0 -m "LocalDocks v0.9.0"` and push the tag.
7. Create the release against that tag: pre-release **on**, latest **off**.
8. Attach the installer and `SHA256SUMS.txt`.
9. Paste the body from section 2 and fill the two marked fields.

### Repository visibility

The repository is currently **private**. A public release requires making it
public, which is irreversible in practice — the security and privacy scan in the
final report is the gate on that, not this document.

## 4 · Not automated, and why

There is no release GitHub Action. Publishing a release automatically means a
workflow with permission to write releases and, eventually, to hold a signing
key — for a project whose first release has not happened yet and whose signing
story is unresolved ([CODE-SIGNING.md](../CODE-SIGNING.md)). The nine steps
above are done by hand, watched, once. Automation is worth revisiting after
there is a release process that has actually run.
