# Contributing to LocalDocks

Thank you for your interest in contributing to LocalDocks.

LocalDocks is being built as an open-source developer tool with a focus on simplicity, performance, and developer experience.

## Before Contributing

Please read the documentation and existing issues before starting work.

For larger changes, open an issue or discussion first so the direction can be discussed before significant implementation work begins.

## Development

The project is currently under active development.

Development instructions, architecture documentation, and setup instructions will be added as the project architecture is finalized.

## Pull Requests

Before opening a pull request:

1. Make sure your changes are focused on a specific problem or feature.
2. Test your changes locally.
3. Keep unrelated changes out of the pull request.
4. Update documentation when necessary.
5. Explain what was changed and why.
6. Include screenshots or recordings for significant UI changes when appropriate.

## Commit Messages

Keep commit messages concise and descriptive.

Examples:

```text
feat: add port discovery
fix: handle inaccessible processes
docs: update installation guide
refactor: simplify process scanner
```

## Code Quality

Prefer code that is:

- Simple
- Readable
- Maintainable
- Well-tested where practical
- Consistent with the existing architecture

Avoid introducing dependencies unless they provide meaningful value.

## Issues

Use the appropriate issue template when reporting bugs, requesting features, or asking questions.

## Code of Conduct

All contributors are expected to follow the project's [Code of Conduct](CODE_OF_CONDUCT.md).
